Maderas Nexo: empresa y plantilla

Maderas Nexo es una empresa ficticia de venta y distribución de madera y tableros. Dispone de una sola sede con oficinas y almacén, y una plantilla de 30 empleados.

Grupos y recursos: modelo AGDLP

Se sigue el modelo AGDLP: cuentas → grupos globales de departamento → grupos de dominio local del recurso → permisos.

adm01→ GG_MN_ADM→ DL_MN_ADM_M→ Carpeta Administración

Se definen 6 grupos globales y 12 de dominio local: seis para modificar cada carpeta departamental, cinco de lectura para Dirección sobre los otros departamentos y uno para modificar Común.

La nomenclatura usa GG_MN_CODIGO, DL_MN_CODIGO_M para modificar y DL_MN_CODIGO_L para leer. Ejemplos: GG_MN_DIR, GG_MN_ADM, DL_MN_ADM_M y DL_MN_ADM_L. Los códigos son DIR, ADM, COM, CMP, ALM y LOG. El recurso compartido Común se asocia a DL_MN_COMUN_M.

Dirección puede modificar su carpeta y leer las otras cinco. Los miembros de cada departamento pueden modificar su carpeta y Común. No se concede acceso a las carpetas privadas de otros departamentos. Esto se plantea para usuarios normales, sin alterar los accesos administrativos necesarios para gestionar los recursos.

Alcance: en esta actividad se crean las entidades y pertenencias de Active Directory y se diseña la matriz de recursos. Crear grupos no aplica automáticamente permisos SMB o NTFS. Las carpetas y sus ACL se documentan como diseño; una prueba real de acceso sería una ampliación aparte.

CONCEPTOS

Ámbito y tipo de grupo

Son dos decisiones independientes: ámbito determina miembros y alcance; tipo indica su función.

ÁmbitoMiembrosDónde concede permisosUso
GlobalCuentas y grupos globales del mismo dominio.Dominios del bosque o con confianza.Agrupar departamentos: GG_MN_ADM.
Dominio localCuentas, globales y universales de dominios admitidos por confianza; otros DL del mismo dominio.Su propio dominio.Asignar acceso al recurso: DL_MN_ADM_M.
UniversalCuentas, globales y universales del mismo bosque.Bosque y relaciones de confianza aplicables.Agrupar funciones entre varios dominios. Aquí no se necesita.
TipoFinalidad
SeguridadPuede recibir permisos. También puede habilitarse para correo con infraestructura compatible.
DistribuciónListas de correo; no sirve para asignar permisos. Requiere un sistema de correo que utilice el grupo.

En esta práctica: Global + Seguridad para reunir empleados; Dominio local + Seguridad para permisos. Crear el grupo no configura automáticamente la carpeta.

Primer ejemplo mediante interfaz gráfica

La práctica empieza con un ejemplo en Administración, desde dsa.msc en SRV-DC01:

  1. En asix.test crear la OU MaderasNexo, manteniendo la protección contra eliminación accidental.
  2. Dentro, crear Administracion con sus OU Usuarios y Equipos. Crear también Grupos con Globales y DominioLocal.
  3. En Usuarios de Administracion, crear Administracion 01, inicio adm01@asix.test y nombre corto ASIX\adm01. Establecer una contraseña personal y exigir su cambio al primer inicio.
  4. En Globales, crear GG_MN_ADM, tipo Seguridad y ámbito Global.
  5. En DominioLocal, crear DL_MN_ADM_M, tipo Seguridad y ámbito Dominio local.
  6. En Miembros de GG_MN_ADM, añadir adm01.
  7. En Miembros de DL_MN_ADM_M, añadir GG_MN_ADM.

La primera cadena AGDLP queda creada sin asignar permisos directos a la cuenta. No se hace al usuario administrador ni se utiliza una contraseña visible en la documentación.

VERSIÓN ESCRITORIO

Completar las OU mediante las ventanas

Tras el ejemplo inicial de Administración se han creado manualmente Direccion, Comercial, Compras, Almacen y Logistica, cada una con Usuarios y Equipos. Todas se sitúan dentro de MaderasNexo. Usuarios y Equipos son OU hermanas, no una dentro de otra.

Al corregir una OU vacía creada en una ubicación incorrecta, se utilizó Ver → Características avanzadas → Propiedades → Objeto para retirar su protección contra eliminación accidental. Después se eliminó únicamente esa OU vacía y se recreó en la ubicación correcta, conservando la protección de las demás.

Como comprobación final se ejecutó una consulta de solo lectura por PowerShell para visualizar el árbol. Los objetos de esta versión se crearon gráficamente; la consulta no los crea ni modifica.

Consulta de comprobación · mostrar el árbol
Import-Module ActiveDirectory
function Mostrar-ArbolAD {
    param([string]$Ruta, [string]$Sangria = '')
    $objetos = @(Get-ADObject -SearchBase $Ruta -SearchScope OneLevel -Filter * |
        Sort-Object ObjectClass, Name)
    for ($i = 0; $i -lt $objetos.Count; $i++) {
        $objeto = $objetos[$i]
        $ultimo = $i -eq ($objetos.Count - 1)
        $rama = if ($ultimo) { '└── ' } else { '├── ' }
        Write-Host "$Sangria$rama[$($objeto.ObjectClass)] $($objeto.Name)"
        if ($objeto.ObjectClass -eq 'organizationalUnit') {
            $continuacion = if ($ultimo) { '    ' } else { '│   ' }
            Mostrar-ArbolAD -Ruta $objeto.DistinguishedName -Sangria ($Sangria + $continuacion)
        }
    }
}
